## 1. Why this is a request, not an edit

เพิ่มขั้น "ยืนยันในแชต LINE" (การ์ด postback) ก่อนบันทึกเข้าพอร์ต — เปลี่ยนจุดที่ commit holding (จาก submit บนเว็บทันที → รอผู้ใช้กดคอนเฟิร์มในการ์ด) และเพิ่มการจัดการ postback event ใน webhook จึงเป็นคำขอ

## 2. ข้อจำกัดที่กำหนดดีไซน์ (อธิบาย + เลือกแนวทางกับเจ้าของแล้ว)

- **"จำนวนเงิน"** ตอนสลิปเข้ามา เซิร์ฟเวอร์เห็นแค่รูป → การอ่านเลขอัตโนมัติต้อง OCR ฝั่งเซิร์ฟเวอร์ (เสียเงิน) · เลี่ยงด้วยการใช้ OCR ฝั่งเบราว์เซอร์ (Tesseract ฟรี, CR-WPN-003) บนฟอร์ม
- **"จำนวนหน่วย"** ไม่มีบนสลิปเลย (สลิปบอกแต่บาท) → ต้องให้ผู้ใช้พิมพ์ · การ์ด LINE กดปุ่มได้อย่างเดียว พิมพ์ไม่ได้ → ต้องกรอกบนฟอร์มเว็บก่อน
- **เจ้าของเลือกแนวทาง (ก):** ฟอร์มเว็บสั้น (OCR เติมเงิน/ประเภท, ผู้ใช้กรอกจำนวนหน่วย) → ย้ายขั้น "ยืนยัน" ไปเป็นการ์ดใน LINE (ไม่เสียเงิน, ไม่ใช้ LIFF)

## 3. Request

### CR-09 · การ์ดคอนเฟิร์ม/ยกเลิก → บันทึกเข้าพอร์ต → การ์ดสำเร็จ

| Item | Value |
|---|---|
| Document | REQ-WPN-001 F009→F001 (ขั้นยืนยันเข้าพอร์ต) |
| ระดับ | เพิ่มเติม (เปลี่ยน UX จุด commit) |

**Proposed change / flow**

```
ส่งสลิป → [LINE reply] "ได้รับสลิป" + [บันทึกสลิป]
   → เว็บ /slips (OCR เติมเงิน/ประเภท) → "เพิ่มเข้าพอร์ต"
   → เว็บ /add (กรอกชื่อ + จำนวนหน่วย) → "ส่งสรุปไปยืนยันใน LINE"
   → [LINE การ์ดคอนเฟิร์ม] "ตรวจสอบก่อนบันทึก: PTT · 10 หน่วย · ttb · มูลค่า ฿X"
        [ ✅ คอนเฟิร์ม ]   [ ✖ ยกเลิก ]           ← ปุ่ม postback
   → กดคอนเฟิร์ม → บันทึกลง Supabase → [LINE การ์ดสำเร็จ] "✅ บันทึกเข้าพอร์ตสำเร็จ …" + [ 📊 ดูพอร์ต ]
   → กดยกเลิก → ทิ้งรายการ → "ยกเลิกแล้ว ❌"
```

**สถาปัตยกรรม (decide-and-log):**
- `/api/holdings/stage-confirm` — แทน insert ตรง: validate → **พักรายการใน KV** (`hold:<id>`, TTL 1 ชม., `holdStage.ts`) → **push buttons template** (ปุ่ม postback `holdok:<id>` / `holdno:<id>`) ไป messaging userId (จาก claim.u ที่ร้อยจากสลิป)
- webhook เพิ่มการจัดการ **postback event**: `holdok` → โหลดจาก KV (ตรวจ `source.userId === msgUser`) → `insertHolding` → reply การ์ดสำเร็จ + ปุ่มดูพอร์ต · `holdno` → ลบรายการพัก → reply "ยกเลิกแล้ว" · หมดอายุ/ไม่พบ → แจ้งให้ส่งใหม่
- `lineApi.buttonsMessage` รองรับทั้งปุ่ม `uri` และ `postback` (union `LineAction`)
- **เพิ่มด้วยมือ** (ไม่ได้มาจากสลิป) ยังบันทึกตรงผ่าน `/api/holdings` (CR-WPN-006) — เฉพาะสลิป (มี claim) ใช้เส้นทางการ์ด
- ลบ push "จังหวะ 3" ของ CR-WPN-005 ออก (การ์ดคอนเฟิร์ม/สำเร็จแทนแล้ว)

**Impact** — effort: `lineApi` (postback action) · `holdStage.ts` (KV) · `/api/holdings/stage-confirm` · webhook (postback) · `/add` (routing + ปุ่ม) · `portfolio.holdingSummary` + test · **ไม่มี Class B เพิ่ม** (ใช้ KV/LINE token/Supabase ที่ตั้งค่าแล้ว)

**ของที่ยังไม่พร้อม/ข้อควรรู้:** ปัจจุบันต้องผ่าน 2 หน้าเว็บ (/slips ตรวจสลิป → /add กรอกจำนวน) ก่อนถึงการ์ด — ยัง "รวบเป็นฟอร์มเดียว" หรือ "ข้ามหน้าชีต" ไม่ได้ในรอบนี้ (จะทำเป็น iteration ถัดไปถ้าต้องการ) · อยากกรอกในแอป LINE ล้วน = ต้องทำ LIFF (งานแยก)
