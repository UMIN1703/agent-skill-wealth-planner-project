## 1. Why this is a request, not an edit

การทำให้สลิป (F009) กลายเป็นรายการถือครองในพอร์ต (F001/F002) เป็นการ **เชื่อม 2 ฟีเจอร์เข้าด้วยกัน** ที่ไม่มีใน AC เดิมของทั้งสองฝั่ง และแตะเรื่องชั้นข้อมูล (persistence) ซึ่งเป็น Class B (Supabase, รอ creds) จึงออกเป็นคำขอ ไม่ใช่แก้เงียบ

## 2. ช่องว่างเชิงโมเดล (ที่ทำให้ต้องเลือกดีไซน์)

สลิปเป็น **ธุรกรรม** (มี: ยอดบาทรวม, วันที่, ประเภท deposit/buy/sell/fee, หมวดหมู่สินทรัพย์, ช่องทาง) แต่ **ไม่มี ชื่อสินทรัพย์ + จำนวนหน่วย + ราคาต้นทุน/หน่วย** ซึ่งพอร์ต (holding) ต้องใช้ → สลิปใบเดียวสร้าง holding ครบไม่ได้ ต้องให้ผู้ใช้เติมส่วนที่ขาด

## 3. Request

### CR-06 · สะพาน "เพิ่มเข้าพอร์ต" จากสลิป → เติมฟอร์ม F001 ล่วงหน้า

| Item | Value |
|---|---|
| Document | REQ-WPN-001 F009 (เสริม) + F001 (เสริมการเติมฟอร์มจาก query) |
| ระดับ | เพิ่มเติม (bridge F009→F001) |

**การตัดสิน (decide-and-log, จากคำถามเจ้าของ 2026-11-18):**

1. **รูปแบบการเชื่อม = สลิปเติมฟอร์มเพิ่มสินทรัพย์ (F001)** — ไม่ใช่ให้พอร์ตอ่าน ledger มารวมเอง และไม่ใช่หน้าธุรกรรมแยก · เหตุผล: ตรงกับสถาปัตยกรรมปัจจุบัน ปิดช่องว่าง "ไม่มีชื่อ/จำนวน" ด้วยการให้ผู้ใช้กรอกต่อ ทำได้ทันทีไม่ต้องรอ Class B
2. **ที่เก็บ = mock (session) ไปก่อน** — persistence จริงรอ Supabase (Class B) เหมือน F001 วันนี้ · รายการที่เพิ่มปรากฏในลิสต์ "เพิ่มในเซสชันนี้" ของหน้า /add (reload แล้วหาย — ข้อจำกัดเดิมของ F001)

**Proposed change**

| | Text |
|---|---|
| **Current** | F009 บันทึกสลิปลง Google Sheet จบในตัว · F001 เพิ่มสินทรัพย์ด้วยการกรอกมือล้วน ไม่มีทางลัดจากสลิป |
| **Proposed** | ฟอร์มยืนยันสลิป (SlipReview) มีปุ่ม **"เพิ่มเข้าพอร์ต"** → นำทางไป `/add` พร้อม query (`from=slip` + `type`=หมวดหมู่สินทรัพย์ · `broker`=ช่องทาง · `amount`=ยอดรวม · `name`=บันทึกย่อ) · หน้า /add อ่าน query มา**เติมประเภท/โบรก/ชื่อให้ล่วงหน้า** แสดงแบนเนอร์ "เติมจากสลิปแล้ว" · ผู้ใช้กรอก **ชื่อ + จำนวนหน่วย** ที่เหลือ · เมื่อใส่จำนวน ระบบ**คำนวณต้นทุน/หน่วย = ยอดสลิป ÷ จำนวน** ให้อัตโนมัติ (แก้ทับได้) |

**สถาปัตยกรรม (decide-and-log):** ส่งค่าผ่าน **URL query** (stateless, ไม่ผูก store) · หน้า /add ใช้ `useSearchParams` (ครอบ `Suspense` ตามข้อกำหนด app router) seed `AssetDraft` · โบรกจากสลิป (เช่น `ttb`) ที่ไม่อยู่ในลิสต์มาตรฐานถูกเติมเข้า option ให้เลือกได้ · ต้นทุน/หน่วยไม่ prefill ด้วยยอดรวม (ยอดรวม ≠ ราคา/หน่วย) แต่คำนวณให้เมื่อรู้จำนวน

**Impact** — effort: SlipReview (ปุ่ม+handler) · app/add (Suspense+seed+banner+auto cost) · **ไม่มี Class B / ไม่มีค่าใช้จ่าย** · ไม่กระทบ AC เดิมของ F001/F009 (validation/กันซ้ำเดิมยังทำงาน)

**ของที่ยังไม่พร้อม (คงเป็น Class B):** รายการที่เพิ่มยัง**ไม่คงอยู่ข้ามเซสชัน** และ**ยังไม่ขึ้นหน้า dashboard/พอร์ตรวม** — ทั้งสองต้องมี store กลางจริง (Supabase) ซึ่งเป็น Class B ที่รอ credentials · สลิปฝั่งเงินสด/ค่าธรรมเนียม (deposit/fee) ไม่เหมาะกับ holding เชิงหน่วย — ปล่อยให้ผู้ใช้ตัดสินใจว่าจะเพิ่มหรือไม่
