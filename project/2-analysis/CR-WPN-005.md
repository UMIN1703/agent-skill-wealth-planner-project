## 1. Why this is a request, not an edit

เปลี่ยนรูปแบบการตอบกลับของ F009 webhook (จาก reply ข้อความล้วน → ข้อความแบบปุ่ม) และเพิ่มการ **push** ข้อความจังหวะที่สอง (ซึ่งเดิมไม่มี) จึงกระทบพฤติกรรม AC-01 ของ F009 → ออกเป็นคำขอ

## 2. ข้อจำกัดที่กำหนดดีไซน์

ตอนสลิปเข้ามา (webhook) เซิร์ฟเวอร์เห็นแค่ **รูป** — ยังไม่รู้ "ยอด" เพราะ OCR อ่านฝั่งเบราว์เซอร์ (Tesseract.js หลัง login, CR-WPN-003) การตอบ "สรุปยอด" ทันทีจึงต้องเพิ่ม OCR ฝั่งเซิร์ฟเวอร์ (เสียเงิน) → เจ้าของเลือก **ตอบ 2 จังหวะ** แทน (ฟรี, ได้ยอดจริง)

| **Proposed** | **จังหวะ 1 (reply ทันที):** buttons template "ได้รับสลิปแล้ว ✅" + ปุ่ม [📝 บันทึกสลิป → /slips?claim] [📊 ดูพอร์ต → /] · **จังหวะ 2 (push หลังผู้ใช้ยืนยันบนเว็บ):** confirm route ที่บันทึกลงชีตสำเร็จ จะ **push** buttons template "✅ บันทึกแล้ว ฿1,300 · ฝาก/โอนเข้า · ttb" + ปุ่ม [📊 ดูพอร์ต → /] [📄 ดูชีต → Google Sheets URL ของผู้ใช้] |

**สถาปัตยกรรม (decide-and-log):**
- `lineApi.ts` เพิ่ม `replyLineButtons` / `pushLineButtons` (LINE buttons template · ตัด text ≤160, label ≤20, ≤4 ปุ่ม)
- **push ได้เฉพาะเมื่อรู้ messaging userId** (`claim.u` จากลิงก์ claim) — เพราะ LINE Login userId เป็นคนละตัว push ไม่ได้ (ดู CR-WPN-002/claim-link) · ถ้า login LINE ธรรมดา (ไม่มี claim) → ข้าม push เงียบ ไม่กระทบการบันทึก
- ลิงก์ "ดูชีต" ใช้ `https://docs.google.com/spreadsheets/d/<spreadsheetId>/edit` (ได้ id จาก `saveSlipRow`) — https เปิดได้ทุกที่
- push ล้มเหลว = log ไว้ ไม่ทำให้การบันทึกล้ม (บันทึกชีตคือผลลัพธ์หลัก)

**Impact** — effort: lineApi (+2 fn) · webhook (reply→buttons) · confirm (push) · **ไม่มี Class B เพิ่ม** (ใช้ LINE_CHANNEL_ACCESS_TOKEN เดิม)

**ของที่ยังไม่พร้อม/ข้อควรรู้:** ปุ่ม "บันทึกสลิป"/"ดูพอร์ต" ชี้ไป `AUTH_URL` (ตอนนี้ = http://localhost:3000 สำหรับ dev) → เปิดบนมือถือจริงไม่ได้ ต้องเปิดบนเครื่อง dev (เหมือนลิงก์เดิม) · จะใช้บนมือถือจริงต้องเสิร์ฟผ่านโดเมนสาธารณะ (deploy / ngrok เป็น canonical + ปรับ OAuth redirect) — เป็นงาน deploy (Class B) · ยอดรวมใน "ดูพอร์ต" ให้เป็นของจริงต้องมี Supabase (ดู CR-WPN-006)
